The easy guide to improve-code

What it is, what it does, and the tricky words made simple — written so anyone can follow along.

1What is it?

improve-code is a helper you run through an AI coding assistant (like Claude Code or Codex). You point it at some code that feels messy or hard to follow, and it tidies the code up so both people and AI can read and change it easily — without changing what the program actually does.

Think of it like reorganizing a messy kitchen. The same pots, pans, and food are all still there — but now everything has a labelled place, so anyone can walk in and cook without opening every drawer.

2Why would I want it?

  • Code that is hard to read is hard to change safely — small edits turn into big risky ones.
  • AI assistants now do a lot of the editing, so code also needs to be easy for them to navigate.
  • improve-code fixes both at once, and it checks its work with tests, so nothing quietly breaks.

3The one big idea

Good code has a simple property: changing one thing means touching one place. Messy code is the opposite — to change a little, you hunt across many files and hold the whole thing in your head.

improve-code reshapes code toward the first kind. Everything it does serves that single goal: shrink how much you must understand to make one correct change.

4What it does, step by step

A run always follows the same eight steps, and each one has a clear finish line before the next begins.

  1. Asks your goal. It never guesses — it asks what you want improved and why.
  2. Looks around. It reads the code and runs the existing tests to check they pass.
  3. Finds the problems. It spots known messy patterns ("smells") that are worth fixing.
  4. Agrees a plan. It shows you a short list and lets you choose what to do.
  5. Adds a safety net. It writes tests that capture how the code behaves right now.
  6. Makes the change carefully. One small step at a time, re-running the tests after each.
  7. Tidies names and docs. So the next reader — person or AI — can find their way.
  8. Double-checks and notes it down. Runs everything, shows the proof, records what changed.

5Words explained simply

You will see these terms in the skill. Here they are in plain English.

deep module
A tool with a simple handle hiding complex machinery — like a microwave: one button, lots happening inside. This is the good kind.
shallow module
A wrapper that barely does anything but adds an extra step to get through. More hoops, no benefit — the kind to remove.
blast radius
How many places you must edit to make one change. Smaller is better.
seam
A spot where you can slot in a stand-in (like a crash-test dummy) so a part can be tested safely on its own.
smell
A warning sign that code might be messy. Not a bug — just a hint worth a look.
green tests
All the tests are passing. improve-code only reshapes code while the tests are green.
characterization test
A "before photo" of how the code behaves now, so you would instantly notice if anything changed.
net-complexity gate
A rule the skill lives by: only make a change if it removes more mess than it adds.

6A quick example

Say you have one function that quietly does three jobs and has grown to 200 tangled lines. You ask improve-code to make it easier to work with.

goal

You say: "This function is hard to change — make it clearer, same behaviour."

safety net

It writes tests that pin down exactly what the function returns today.

reshape

It splits out the parts that genuinely stand alone, names them for what they do, and drops any pointless wrappers — one small step at a time, tests green throughout.

tidy

It updates the comments and docs it touched, so the next reader is not misled.

proof

It runs the full test suite and shows you it still behaves exactly the same.

Result: the same program, now readable in a minute instead of an hour — and safe to change.

7What it will not do

So you can relax while it works:

  • It will not change what your program does — the behaviour stays identical.
  • It will not touch code that is unrelated to your goal.
  • It will not reshape code that has no test — it adds a safety net first.
  • It will not make big or risky changes without asking you first.

8How to use it

Install it once for your AI assistant, then just ask.

# install (Claude Code / Codex share one folder here)
git clone https://github.com/cskwork/improve-code-skill
ln -s "$(pwd)/improve-code-skill" ~/.agents/skills/improve-code

Then, in your assistant, start it and answer its first question:

> improve-code
# or simply: "clean up this file" / "make this module easier to change"

9FAQ

Do I need to be a programmer?
No. You drive it through an AI assistant, and it explains what it is doing in plain language as it goes.
Will it break my code?
It works only while tests pass and moves in tiny steps. If a step breaks a test, it undoes that step instead of pushing on.
Is it tied to one tool?
No. It uses whatever code tools your environment happens to have, and works without any special one.
Where do I learn more?
The full skill and its reference docs live on GitHub.
