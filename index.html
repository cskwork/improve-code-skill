Claude Code skill

> improve-code

Refactor so that one correct change needs less context — for an AI agent and a human alike.

Goal-driven, grounded in software fundamentals, and it applies the change under green tests instead of just advising.

The bar

Legible to an agent, and to the next human

Most "clean code" advice optimizes for one reader. This skill holds a dual bar as non-negotiable — and treats every principle as a heuristic a smell triggers, never a rule to apply top-down.

// for the agent

No project memory, a narrow view

Find the behavior from a name, change one bounded area behind a stable seam, and run the smallest verification — without loading the whole system.

// for the human

Reads top-to-bottom, in clear language

Names map to domain concepts, the happy path is un-indented, and the why lives in a comment only where the code cannot say it.

Both must be able to find the behavior, change one bounded place, and verify it — without reading the whole system. If not, the design leaks hidden context, and that is the thing to fix.

Leading ideas

Five words that carry the work

Repeated across the skill so the agent reaches for the same behavior every run.

deep module

A small, stable interface hiding a large implementation. Deepen shallow wrappers; never shred a deep thing into fragments.

blast radius

How many places one change must touch. Good structure keeps it to one — high locality.

seam

Where behavior can be substituted (a fake clock, network, DB). Where tests attach and internals get rewritten safely.

net-complexity gate

A change must remove more to understand than it adds. One implementation behind an interface, with no volatility, fails the gate.

smell → fix

Work only where a smell is present. Absent a smell and a named payoff, leave the code alone.

green tests

Change structure only while tests stay green. One hat at a time: restructure, or add behavior — never both.

How a run goes

Eight steps, each with a checkable gate

It starts by asking your goal, and ends only with evidence.

  1. Set the goal

    Ask what to improve and why — target, payoff, constraints, definition of done. No guessing.

    Done when you restate the goal and the user confirms it.

  2. Explore and pin the ground truth

    Map the target with whatever navigation tools the environment offers; confirm the suite is green.

    Done when current behavior is stated plainly and the test state is known.

  3. Diagnose against the principle set

    Match the code to a smell catalog; keep only fixes that pass the net-complexity gate.

    Done when each item names its smell, principle, fix, and payoff.

  4. Agree the plan

    Recommend the smallest high-leverage set; surface risk and ADR conflicts.

    Done when the user picks the fixes to apply.

  5. Pin behavior with tests

    Add characterization tests to any untested area before touching it.

    Done when every area to be touched is under a green test.

  6. Apply surgically — one hat, small steps

    One named move at a time; green → checkpoint, red → revert and retry smaller.

    Done when every fix is applied and the diff is scoped to the target.

  7. Make it navigable

    Names, docstrings, docs updated in the same diff, one source of truth.

    Done when renames, docs, and commands are all consistent and verified.

  8. Verify and record

    Run the real tests, lint, types, build; report what passed and record the decision.

    Done when checks are green with quoted evidence.

What is in the box

A lean spine, reference on demand

Only SKILL.md loads every run. The rest is disclosed at the step that needs it.

github.com/cskwork/improve-code-skill · a Claude Code skill · tool-agnostic and self-contained

Grounded in Ousterhout (A Philosophy of Software Design), Parnas (information hiding), Fowler & Beck (Refactoring), Feathers (Working Effectively with Legacy Code), Dan North (CUPID), the connascence taxonomy, Diátaxis, and current agent-codebase guidance.

Principles are heuristics, not laws — the skill applies them where a smell is present and the net-complexity gate is passed.
